# ADR 001: Implement Task Status Filtering

**Status**: Accepted
**Date**: 2026-07-09

## Context
Users have too many tasks in the system, making it difficult to find relevant work. Currently, all tasks are returned in a single list, which is not scalable.

## Decision
We will add a `status` query parameter to the `GET /tasks/` endpoint. This allows the client to filter tasks by their current status (e.g., "To Do", "In Progress", "Done").

## Alternatives Considered
* **None**: Leaving the current implementation as-is, which leads to poor user experience as the list grows.

## Consequences
* **Positive**: Users can quickly focus on specific subsets of tasks.
* **Negative**: The backend `GET /tasks/` logic must be updated to handle optional query arguments and modify the database query accordingly.
